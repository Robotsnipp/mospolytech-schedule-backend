# Работа с генератором расписания

- При изменении моделей или правил планирования читай `CONTEXT.md`: там определены предметные термины.
- При изменении генерации, календаря, импорта плана или сохранения результатов читай `.agents/planning.md`: там описаны ограничения реализации и незакрытые проблемы.
- При изменении парсеров, интеграции кабинета или персонального демо читай `.agents/sources.md`: там разделены реальные источники, фикстуры и ещё не реализованные связи.
- При изменении API расписания или dev-панели читай раздел «Выдача результатов» в `.agents/planning.md`: фиксированная ПД хранится отдельно от `ScheduledClass`.
- При изменении моделей создавай миграцию; проверяй применение на отдельной тестовой БД и отсутствие незаписанных изменений моделей.
- Для изменения поведения генератора проверяй реальное решение CP-SAT на небольшом сценарии, а не только вызов функции с моками.
- Команды локальной проверки находятся в разделе «Проверка» в `README.md`. Используй отдельную локальную SQLite-БД или тестовую БД; демо-команда создаёт данные и может заменять расписание своего периода.
- В отчёте различай работоспособность запуска, полноту размещения нагрузки и соблюдение ограничений. Статус `SOLVED` сам по себе не доказывает отсутствие ошибок в правилах.
