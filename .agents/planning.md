# Контекст реализации планирования

## Первая версия

Учебный план принадлежит программе, набору, форме обучения и версии.
Несколько групп могут использовать один план. Номер семестра обучения
в строке плана отличается от календарного семестра конкретного года.

PDF сохраняется как источник; OCR и импорт строк пока не реализованы.
Самостоятельная работа хранится отдельно от часов занятий.
Часы плана пока не преобразуются автоматически в пары или нагрузку модуля:
`LessonEvent.pairs_per_week` задаётся явно.

Генератор строит недельный шаблон выбранного модуля, используя сетку
семестра. Занятия без модуля включаются как общие для семестра.
При наличии модульных занятий модуль требуется явно. Даты модуля
и число учебных недель пока не разворачивают шаблон в календарные пары.
Для заочной формы нельзя предполагать календарь очного обучения.

Площадки объединяют корпуса, корпуса — аудитории. Отключённые аудитории
исключаются из генерации. Тип и оборудование пока описательные поля;
переходы между площадками и автоматический выбор преподавателей не реализованы.

## Фиксированная ПД

`FixedProjectSession` задаёт готовые интервалы; `run_generation` учитывает их
автоматически. Состав берётся из `ProjectEnrollment`, преподаватель — из записи
или руководителя проекта. Общая пара группы/потока конфликтует с ПД любого её
участника, а два проекта с непересекающимися студентами одной группы совместимы.
Фиксированное расписание заменяет генерируемую ПД этого проекта.

Дополнительная площадка занимает время людей без выбора аудитории. Известная
университетская комната блокируется явно. Запас на дорогу вводится в минутах;
маршрутизация отсутствует. Для фиксированной ПД нужны точные времена слотов.
У каждого запуска сохраняется `fixed_pd_snapshot` с составом и источниками.

Датированные интервалы проецируются в недельный шаблон объединением занятости
за выбранный период и чётность. Это консервативно и может дать PARTIAL. Полный
календарь отмен и переносов пока отсутствует. Импорт по явному сопоставлению ID
останавливается на неразобранных календарных примечаниях и подгруппах без состава.
Команда импорта и формат сопоставлений описаны в README, «Фиксированное расписание ПД».

## Результаты

`clear_previous=false` сохраняет несколько запусков. При `true` старые пары
того же семестра и модуля удаляются только после `SOLVED` без пропущенных
событий. По умолчанию параметр всё ещё `true`. Согласованный целевой сценарий:
новая генерация создаёт черновик, действующий вариант меняется после утверждения.
Механизм утверждения пока отсутствует.

## Известные проблемы для отдельных исправлений

- `add_lecture_single_slot()` ограничивает лекцию одной парой в неделю,
  даже если требуется больше.
- В `services/objectives.py` у переменных окна есть только верхние границы:
  решатель может обнулить штраф при фактическом окне.
- Недельный лимит преподавателя хранится, но не применяется.
- `Group.semester` и флаг первого семестра сохранены для совместимости;
  группа должна оставаться постоянной сущностью при смене календарных периодов.
- Выбор ПД рассчитан на один проект у студента; история выбора по учебным
  годам пока не моделируется. По договорённости проект выбирается на год.

После исправления проблемы обнови этот список и добавь тест на соответствующий
сценарий. Учёт новых ограничений проверяй на совместном расписании групп,
использующих общих преподавателей и аудитории.
