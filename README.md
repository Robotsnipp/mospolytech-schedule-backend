# mospolytech-schedule-backend
## Учебные планы и модули

В админке создаются `Curriculum` (программа, набор, форма обучения, срок,
версия и исходный PDF) и `CurriculumEntry` (предмет и часы по семестру
обучения, формы контроля). Группа ссылается на план. Загрузка файла пока
не запускает OCR: строки вводятся вручную. Часы самостоятельной работы
хранятся отдельно от контактных часов.

`Module` задаёт реальные даты и число учебных недель календарного семестра.
`LessonEvent` может ссылаться на модуль и строку плана. `pairs_per_week`
по-прежнему вводится явно: автоматического распределения часов по модулям
и преобразования часов в пары пока нет.

В `POST /api/schedule/generate/` можно передать `module` (ID). Генерируются
занятия выбранного модуля и общие занятия семестра без модуля. Если в семестре
есть модульные занятия, модуль обязателен. Сетка `WeekPattern` пока общая
для семестра; результат остаётся недельным шаблоном, а не календарём дат.

Аудитории связаны с корпусами (`Building`) и площадками (`Campus`).
`is_active=False` исключает помещение из генерации. Тип и оборудование
пока информационные поля; ограничения по оборудованию, переходам и выбор
преподавателей не реализованы.

Повторные результаты можно хранить с `clear_previous=false`.
При `clear_previous=true` старые пары выбранного периода удаляются только
после полного успешного решения без пропущенных событий. Утверждение
действующей версии пока не реализовано. Старые данные без новых связей
сохраняют прежнее поведение.

## Проверка

```sh
SECRET_KEY=local-test-only DB_ENGINE=sqlite python manage.py migrate
SECRET_KEY=local-test-only DB_ENGINE=sqlite python manage.py test schedule_generator
SECRET_KEY=local-test-only DB_ENGINE=sqlite python manage.py generate_demo_schedule --time-limit 3
```

Тесты проверяют реальный решатель, фильтрацию модуля, отключённые аудитории,
сохранение вариантов и ограничения новых моделей. Известные прежние проблемы
пересечений ПД с группами, ограничения лекций одной парой и штрафов за окна
не исправлены в этом изменении.
