# Выгрузка расписаний всех групп rasp.dmami.ru

Отдельный файловый парсер на Python 3.12+, без сторонних зависимостей и записи
в БД. По умолчанию один раз загружает `/semester.json`, затем локально
разбивает расписания на файлы **каждой** группы. Сетки звонков читает из
`/js/main.js`. Старый поочерёдный обход `/site/group` доступен с `--group-api`:
он нужен только для серверов, где эта ручка работает. Ошибка
`500: use /semester.json or /session-file.json` означает, что нужен общий файл.

## Запуск из корня backend

Все группы:

```powershell
.\.venv\Scripts\python.exe -u prototypes/dmami_parser/parse.py --output output/parser-prototype/dmami
```

Или `uv run --no-project --python 3.12 prototypes/dmami_parser/parse.py --output output/parser-prototype/dmami`.

Одна/несколько групп для проверки:

```powershell
.\.venv\Scripts\python.exe -u prototypes/dmami_parser/parse.py --group 241-3210 --group 231-338 --output output/parser-prototype/dmami-sample
```

По умолчанию пауза между началами запросов — не меньше 0,5 с, таймаут 20 с,
до двух повторов сетевой ошибки/HTTP 429/5xx с задержкой. Настройка:
`--delay 1 --timeout 30 --retries 2`. Запросы последовательные. В обычном режиме
число запросов не зависит от числа групп; обход сотен запросов требуется только
в старом режиме `--group-api`.

Локально сохранённые источники (без сети):

```powershell
.\.venv\Scripts\python.exe prototypes/dmami_parser/parse.py --semester-json /path/to/semester.json --main-js /path/to/main.js --output output/parser-prototype/dmami-local
```

Реальный сохранённый файл содержит словарь групп в `contents`; также поддерживается
словарь на верхнем уровне либо в `groups`, `schedules`, `data`.
Каждая запись содержит `grid` и `group` с метаданными
(либо метаданные рядом с `grid`). Другой формат вызывает явную ошибку,
не превращаясь в успешную пустую выгрузку. Исходный общий файл сохраняется
в `source/semester.json` до разбора, включая неизвестный формат.
Метаданные `date`, `time`, `v`, `copyright` сохраняются отдельно от времени загрузки.
Проверенный файл опубликован 30.04.2025: успешный разбор не означает актуальность
расписания для текущего семестра. `/session-file.json` не обрабатывается:
режим сессии требует отдельной проверки схемы.

Офлайн из сохранённого HAR (без сети):

```powershell
.\.venv\Scripts\python.exe prototypes/dmami_parser/parse.py --har C:/Users/chsnk/Downloads/rasp.dmami.ru.har --output output/parser-prototype/dmami-har
```

В HAR-режиме по умолчанию экспортируются только группы, чьи ответы сохранены
в файле. Каталог может содержать больше групп. Cookies, заголовки авторизации
и запросы аналитики не копируются; исходное время записи ответа сохраняется.

## Результат

- `schedule.json` — общая выгрузка: группы, правила занятий, источники,
  предупреждения, ошибки и счётчики полноты.
- `schedule.csv` — общая плоская таблица правил, UTF-8 BOM, защита от CSV-формул.
- `groups/<sha256 имени>.json` и `.csv` — отдельные файлы каждой успешной группы;
  соответствие имени и файла есть в `schedule.json`. Имена источника не используются
  в путях, чтобы избежать недопустимых символов и выхода за каталог.
- `catalog.json` — каталог групп с метаданными и три сетки времени звонков.
- `source/home.html`, `source/main.js`, `source/groups/<sha256>.json` — исходные
  ответы. Для источников сохраняются SHA-256, URL и время получения.
- В обычном режиме полный неизменённый источник — `source/semester.json`.
  Отдельные файлы `source/groups` помечены `snapshot_kind=extracted_group`:
  это извлечённые представления, а `document` и `json_pointer` указывают
  на оригинальный общий файл и его хеш. Время получения локального файла
  неизвестно и остаётся `null`.

`complete=true` означает успех всех **запрошенных** групп.
`covers_entire_catalog=true` — успех всего каталога. Ошибка отдельной группы
не останавливает остальные; группа попадает в `errors`, процесс завершается с
кодом 1. Ошибка каталога/временной сетки останавливает запуск до обхода групп.
HTTP 200 с `status=error` тоже считается ошибкой. Повторять лучше в новый каталог:
отдельные файлы прошлой выгрузки не удаляются, актуальный состав определяется
только текущим `schedule.json`, а не обходом папки `groups`.

## Сохранение смысла и ограничения

Выгружаются **правила недельного расписания с периодами**, а не готовый календарь
дат. Все элементы массива одного слота сохраняются. Преподаватели с внешними ID,
исходные аудитории, HTML подписей мест, ссылки, периоды и исходный объект занятия
остаются в JSON. Текст и ссылки из `auditories[].title` извлекаются отдельно:
там встречаются вебинары и таблица ПД даже при пустом `e_link`.

Время слотов читается из опубликованного `main.js` по `group.evening`, а не
предполагается одинаковым для всех групп. При изменении структуры источника
парсер останавливается; неизвестный режим/слот даёт `null` времени и предупреждение.
Непустой `week` сохраняется буквально с `uninterpreted_week_pattern`: семантика
чётности в исходном HAR не подтверждена. Подгруппы из названий не угадываются.
Все группы и занятия имеют `review_required=true`.

`session=1`, календарные переносы и автоматическое обновление
не реализованы этим скриптом. Общая запись ПД не содержит состав проекта:
для конкретной ПД по-прежнему нужен отдельный парсер опубликованной таблицы.
Парсер не обращается к личному кабинету.

## Загрузка в Django / db.sqlite3

После `manage.py migrate`:

```powershell
.\.venv\Scripts\python.exe manage.py import_dmami_schedule output/parser-prototype/dmami/schedule.json --dry-run
.\.venv\Scripts\python.exe manage.py import_dmami_schedule output/parser-prototype/dmami/schedule.json
```

Команда использует настроенную БД Django. В локальной конфигурации с
`DB_ENGINE=sqlite` это `db.sqlite3`. Импорт атомарный; повтор того же файла
возвращает ID существующего импорта без дубликатов. Неполные выгрузки отклоняются.
Другой файл создаёт отдельный снимок; `--dry-run` выполняет проверки и откатывает
все записи.

Таблицы: `schedule_generator_scheduleimport`,
`schedule_generator_importedgroupschedule`, `schedule_generator_importedlesson`.
Периоды, время, преподаватели, все варианты мест и исходные значения сохраняются.
Дата публикации источника хранится отдельно от даты импорта. Данные остаются
непроверенными (`review_required=true`). Вместимость комнат, участники проектов,
идентичность преподавателей по одной строке не выдумываются.

Просмотр в Django admin: «Импорты расписания», «Импортированные группы»,
«Импортированные занятия». Поиск занятий — по группе, предмету, преподавателю.
Это отдельные опубликованные расписания; существующие `LessonEvent`,
`ScheduledClass`, результаты решателя и dev-панель генерации не переписываются.
Подключение этих данных к frontend/API — отдельный шаг.

### Преподаватели и API опубликованного расписания

Импорт создаёт `Teacher` с устойчивыми локальными ID и связи
`ImportedLesson.teachers` (многие ко многим). Повтор команды для уже загруженного
файла также заполняет отсутствующие связи преподавателей, без нового импорта.

Если в источнике есть `teachers[].id`, используется внешний идентификатор.
Иначе `teacher_raw` разделяется по запятым; нормализуются пробелы, Unicode и регистр.
Полностью совпадающие нормализованные подписи получают один ID во всех импортах.
Инициалы, опечатки, е/ё и похожие ФИО не объединяются. Полных тёзок без внешних ID
источник различить не позволяет. Записи с внешним ID и без него автоматически
по имени не склеиваются. Существующие ручные/демо-преподаватели не объединяются
с импортом по одному совпадению имени.

Пустые подписи не создают преподавателя. `Вакансия...` — не человек: такие подписи
остаются в исходнике и `teacher_warnings`, ID преподавателя им не назначается.
Исходное поле `data` не изменяется при сопоставлении.

Открытые GET-маршруты (только чтение, стандартная пагинация):

```text
GET /api/schedule/imported/teachers/?search=Козлов
GET /api/schedule/imported/teachers/?import_id=1
GET /api/schedule/imported/teachers/123/
GET /api/schedule/imported/teachers/123/schedule/?import_id=1
```

`123` — пример локального ID; возьмите реальный из поиска. Поиск ФИО учитывает
кириллический регистр. Список преподавателей содержит только людей, связанных
с импортированными занятиями. Расписание выбирается по точному ID преподавателя;
без `import_id` используется последний импорт в БД. Отсутствующий ID — 404,
неправильный параметр — 400.

Ответ расписания: `teacher`, `schedule_import` (включая дату источника),
`count`, `next`, `previous`, `results`. В занятии есть преподаватели с локальными
ID, группа, день 1–7, время, период, `week_raw` и исходный `data`.
Общие пары разных групп остаются отдельными исходными записями; это правила
по периодам, не развёрнутый календарь дат. Чётность `week_raw` пока не интерпретируется.
CRUD и API расписания генератора сохраняют прежнее поведение.

## Проверка

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s prototypes/dmami_parser -p 'test_*.py'
```

Тесты проверяют несколько правил одного слота, HTML-ссылки, внешние ID,
неизвестные периоды/сетки, логические ошибки HTTP 200, неполный экспорт,
исходные хеши, повтор сетевых ошибок и офлайн HAR без утечки cookies.
