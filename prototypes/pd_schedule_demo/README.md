# Персональное расписание с фиксированной ПД

Запуск из корня репозитория с установленными зависимостями:

```sh
.venv/bin/python -m prototypes.pd_schedule_demo.run
```

Прототип создаёт временную SQLite-БД, применяет миграции, импортирует ПД через
`import_fixed_pd` и вызывает настоящий `run_generation`. Рабочая БД не используется.
При повторном запуске создаётся новая временная БД. Результаты:

- `output/parser-prototype/activities/pd-personal-demo/index.html` — расписания четырёх студентов;
- `output/parser-prototype/activities/pd-personal-demo/report.json` — сопоставления и результат проверок.

Сначала строится общее расписание трёх групп; затем у каждого студента выводятся
пары его группы/потока и только его ПД. Два студента из разных групп участвуют
в одном проекте. Ещё один студент той же группы не участвует в ПД, а четвёртый
принадлежит независимой группе. Три предмета по две пары на группу и одна общая
лекция дают 19 размещаемых пар; ПД добавляет два фиксированных интервала.

После решения независимо проверяются полнота нагрузки, наличие обоих интервалов
ПД, пересечения студентов, преподавателей и помещений, а также запас на дорогу
между обычными парами и ПД. Ошибка завершает команду с ненулевым кодом.
Между обычными парами маршрутизация пока не реализована в основном генераторе.

## Источники и границы фикстуры

`fixture.json` содержит проверенную вручную связку:

- ID в кабинете: `4330`;
- название: «Лаборатория интеллектуальных систем [1]»;
- номер строки проекта в опубликованном расписании: `292`;
- ПД: понедельник 12:20–13:50, Н405; среда 16:10–17:40, АВ4310.

Расписание — сокращённый фрагмент результата парсера от 20.10.2026. Поле
`pd_document.source.sha256` относится к полному исходному HTML, а не к этому
JSON. Исходные контактные поля исключены. Номер строки таблицы, ID кабинета
и первичный ключ `Project` в нашей БД — три разных значения.

ФИО студентов, GUID с префиксом `fixture-`, тестовые группы 241-9901/241-9902/241-9903, состав проекта,
учебная нагрузка, обычные преподаватели и вместимость аудиторий **синтетические**.
Это не выгрузка реального состава и не реальное учебное расписание.
30 минут на дорогу — заданное условие демо, не расчёт маршрута.

`FixturePortal.students_in_project(pid)` имитирует результат наблюдаемого запроса:

```http
POST https://e.mospolytech.ru/cpd_api.php
Content-Type: application/x-www-form-urlencoded

act=GPgetStudentsInPrj&pid=4330
```

Наблюдаемые поля: `fio`, `guid`, `grp`, `pname`, `checked`. Автоматический сетевой
клиент и хранение авторизации не реализованы. Значение `checked` не используется
для фильтрации: его предметный смысл ещё не подтверждён. Вариант `all=1` вернул
только текущего пользователя, поэтому его нельзя считать полной выгрузкой.

Ручка каталога `ID → название → учебный период` пока не найдена. Проверенные
страницы кабинета: ПД, форма заявок, «Мои заявки»; публичные `adm.js` и
`jquery_dev.js` не содержат вызова каталога. Функция `getAllProjects()` только
открывает модальное окно; содержимого списка сейчас нет в DOM. Проект `4331`
вернул пользователю 25 записей состава, но его название/период не установлены;
он в фикстуру не включён.

Следующий шаг для живого источника — наблюдать запрос при открытии доступного
каталога в интерфейсе или получить документированный экспорт у владельцев API.
После этого транспорт можно заменить, сохранив формат фикстуры и проверенное
сопоставление с расписанием. Доступность двух ID не доказывает полноту каталога
или актуальность всех составов. Учёт внешних ID в моделях и обновление составов
без удаления исторических данных потребуют отдельной реализации.
