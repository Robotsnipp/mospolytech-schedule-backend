# Парсеры расписаний ПД и физкультуры

Парсеры извлекают проверяемые кандидаты занятий из опубликованного листа
Google Sheets и PDF физкультуры. Результат — JSON/CSV, исходные значения
и предупреждения. Записи БД создаются отдельным импортом ПД.

## Запуск

Из корня репозитория, Python 3.12 и uv:

```sh
uv run --no-project --python 3.12 prototypes/activity_parser/parse.py \
  --pd-url 'https://docs.google.com/spreadsheets/d/e/2PACX-1vRHgwt89VM13uuUy8dDvpjlb-BDM4ovsIKhoLDGIaI58NJtAawxABVW7sdVRDDH5UGaM2bsryni6Im7/pubhtml?gid=643150359&single=true' \
  --pe-pdf /path/to/Raspisanie_dlya_studentov_2-3_kursov_osen_15_10_2026.pdf \
  --output output/parser-prototype/activities
```

Можно передать только один источник. Офлайн-разбор сохранённого листа:

```sh
uv run --no-project --python 3.12 prototypes/activity_parser/parse.py \
  --pd-html output/parser-prototype/activities/pd-source.html \
  --output output/parser-prototype/activities-replay
```

При совместных `--pd-url` и `--pd-html` URL сохраняется как метаданные,
сеть не используется. Онлайн-загрузка читает конкретный `gid` через
`/pubhtml/sheet`: оболочка `/pubhtml` не содержит строк таблицы.

Результаты: `pd.json`/`pd.csv`, `pe.json`/`pe.csv` для выбранных источников.
Сохраняются исходный HTML/PDF, SHA-256 и время разбора. CLI не создаёт
HTML-отчёты и изображения PDF; страница и координаты ячеек остаются в JSON.
В исходниках могут быть опубликованные контакты преподавателей: локальные
выгрузки исключены из Git через `output/parser-prototype/`.

## ПД: контракт результата

- Заголовки определяют таблицу; `rowspan`/`colspan` разворачиваются с сохранением
  координат исходной ячейки, например `G6`.
- Номер, название проекта, преподаватель и исходный текст сохраняются буквально.
  Номер проекта в таблице не является ID кабинета или PK нашей БД.
  Одноимённые проекты и варианты `[1]`/`[2]` не объединяются.
- Каждый явный интервал становится кандидатом. Точное время сохраняется:
  `13:00–16:00` блокирует стандартные пары `[3, 4]`, а не округляется до них.
  Границы полуоткрытые; `start_minute`/`end_minute` доступны отдельно.
- `weekly_candidate` требует подтверждения повторения. `dated` означает
  конкретную дату. Год выводится из указанного учебного года; неизвестный год
  не угадывается. Переносы без полного интервала остаются в `notes`/`changes`.
- У датированного изменения без места наследуется единственное базовое место,
  с отметкой `place_inherited` и происхождением. При нескольких местах выбора нет.
- Аудитории разбираются по легенде документа. Несколько комнат сохраняются
  списком; `АВ4108 (1)/(2)` — подтверждённые номера подгрупп.
  Замена преподавателя хранится в `teacher_override_raw`.
- Полные адреса классифицируются отдельно от аудиторных обозначений.
  Прянишникова, 2А и Автозаводская, 16с13 подтверждены как университетские;
  ссылки на официальные источники сохраняются в `venue.source_url`.
  Остальные адреса текущей выборки — дополнительные места: время людей занято,
  новые пары туда не назначаются, университетская аудитория не резервируется.
  Это категория планирования, а не доказательство принадлежности партнёру.
- У всех записей `review_required=true`, включая записи без предупреждений.
  Снятие предупреждения не означает автоматическую проверку комнаты или маршрута.

Проверенные интервалы подключаются через `manage.py import_pd_schedule`
с явным сопоставлением проектов, преподавателей и комнат. Связи участников
должны существовать в `ProjectEnrollment`; парсер сам импорт не запускает.
Команда, формат сопоставлений и ограничения календаря описаны в корневом README,
раздел «Фиксированное расписание ПД».

## Физкультура: контракт результата

PDF содержит пять страниц — пять временных интервалов, по шесть дней на странице.
Профиль `mospolytech-pe-autumn-2026` восстанавливает таблицу по линиям и читает
текстовый слой без OCR. Другой шаблон или скан требует отдельной проверки.
Неожиданная структура вызывает ошибку; адрес без активности сохраняется
в `orphan_place_cells`.

Запись — предложение, а не назначение студенту. День, точное время, активность,
места, исходный текст, страница и координаты сохраняются. Несколько мест
остаются списком вариантов. Для объединённых активностей выбор происходит
на месте: `activity_choice_mode=on_arrival`; предложение не дублируется.
СМГ помечается `health_group=special_medical_group`. Допуск, вместимость,
преподаватели, точные даты и требование посещать дважды в неделю из PDF не выводятся.
Подключение предложений физкультуры к генератору пока не реализовано.

## Проверка

```sh
uv run --no-project --python 3.12 --with pdfplumber \
  python -m unittest discover -s prototypes/activity_parser -p 'test_*.py'

python -m prototypes.activity_parser.check_sample output/parser-prototype/activities
```

Unit-тесты проверяют структуру таблиц, аудитории, даты, нестандартное время,
СМГ и безопасный CSV. `fixtures/verified_sample.json` — вручную проверенные
ожидаемые значения и хеши конкретных исходников; проверяющий скрипт сравнивает
с ними реальные выгрузки. Парсеры этот файл не читают.

Контрольный документ содержит 323 проекта ПД и 669 явных интервалов;
PDF физкультуры — 150 предложений с 203 местами. Это результат конкретных
источников, а не гарантия точности других документов или проверки всех ячеек.
