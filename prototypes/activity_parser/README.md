# Прототипы разбора ПД и физкультуры

Прототипы извлекают проверяемые кандидаты занятий из опубликованного листа
Google Sheets и предоставленного PDF физкультуры. Результат — JSON, CSV
и общая HTML-страница сверки. Модели, БД и решатель не изменяются.

## Запуск

Из корня репозитория, Python 3.12 и uv:

```sh
uv run --no-project --python 3.12 prototypes/activity_parser/parse.py \
  --pd-url 'https://docs.google.com/spreadsheets/d/e/2PACX-1vRHgwt89VM13uuUy8dDvpjlb-BDM4ovsIKhoLDGIaI58NJtAawxABVW7sdVRDDH5UGaM2bsryni6Im7/pubhtml?gid=643150359&single=true' \
  --pe-pdf /path/to/Raspisanie_dlya_studentov_2-3_kursov_osen_15_10_2026.pdf \
  --output output/parser-prototype/activities
```

Можно передать только один источник. Для офлайн-повтора ПД:

```sh
uv run --no-project --python 3.12 prototypes/activity_parser/parse.py \
  --pd-html output/parser-prototype/activities/pd-source.html \
  --output output/parser-prototype/activities-replay
```

`--pd-url` вместе с `--pd-html` сохраняет ссылку как метаданные, повторной
загрузки не делает. Онлайн-загрузка читает конкретный `gid` через
`/pubhtml/sheet`; оболочка `/pubhtml` сама по себе не содержит строк таблицы.
Для обновления запустить с URL без `--pd-html`.

```sh
python -m http.server 8789 --bind 127.0.0.1 \
  --directory output/parser-prototype/activities
```

Открыть `http://127.0.0.1:8789/review.html`. Есть поиск, выбор источника
и фильтр предупреждений. Для физры у каждой записи доступен фрагмент PDF.
У ПД сохранены исходные ячейки и настоящие координаты листа (например, `G6`).
Страница `warnings.html` группирует предупреждения по причинам и объясняет
следующее действие. Из неё можно открыть записи нужного типа; тот же фильтр
доступен в `review.html`. Если в каталоге лежат `pd-before-warning-fixes.json`
и `pe-before-warning-fixes.json`, отчёт сравнивает их с новой выгрузкой только
при совпадении SHA-256 источника. Эти файлы влияют только на отчёт сравнения.
В исходных ячейках есть опубликованные контактные данные преподавателей;
выгрузки предназначены для локальной проверки и исключены из Git.

## ПД

- Таблица выбирается по заголовкам; `rowspan`/`colspan` разворачиваются
  с сохранением координат исходной ячейки.
- Сохраняются номер строки источника, номер проекта, точное название,
  направление, преподаватель и контактная информация без попытки угадать ФИО.
- Несколько интервалов с общей аудиторией превращаются в отдельные кандидаты.
  Если аудитории указаны после каждой пары, соответствие сохраняется.
- Префиксы аудиторий разбираются по легенде в самом документе. Несколько
  аудиторий показываются списком (`listed_without_student_assignment`),
  персональное назначение не выбирается. Полные адреса сохраняются для
  классификации; полный адрес сам по себе не означает стороннюю площадку.
  Проверенные адреса и источники собраны в `research/campus-addresses.md`.
- Подпись `А12 («Космос»)` разбирается как номер и пояснение. Варианты
  `Н206/Н205` и `АВ2509 (АВ2102 лаборатория)` сохраняют обе аудитории.
  По уточнению пользователя, `АВ4108 (1)/(2)` — номера подгрупп, сохраняемые
  в `subgroup_number`, без создания новых помещений. Другие числовые подписи
  не трактуются автоматически. У внешнего адреса
  номер `Б204` не использует университетскую локацию по умолчанию.
- `place_details` отличает аудитории, университетские и дополнительные адреса и неразобранный текст,
  сохраняет пояснения и внешние номера помещений. Инициалы преподавателя
  из примечания хранятся отдельно в `teacher_override_raw`, без автоматического
  изменения назначения преподавателя.
- Время сохраняется буквально. Отклонения вроде `09:00–10:20` или
  `14:40–16:00` не исправляются до стандартной сетки; `lesson_number=null`.
  `blocked_lesson_numbers` содержит все пересекающиеся стандартные пары,
  например для `13:00–16:00` — `[3, 4]`. Границы интервалов полуоткрытые,
  поэтому окончание ровно в начале следующего слота не блокирует его.
  `start_minute`/`end_minute` сохраняют точное время для будущего расчёта дороги.
- `recurrence=weekly_candidate` означает предположительно повторяющуюся пару,
  требующую подтверждения периода. `recurrence=dated` — отдельную дату,
  а не еженедельное занятие. Год даты без года определяется по явно указанному
  учебному году: сентябрь–декабрь относятся к первому, январь–август ко второму.
- Датированные изменения с собственным временем выделяются отдельно.
  Переносы и замены места без времени сохраняются в `notes`, без выдуманного
  интервала или автоматической отмены основной пары. Несколько дат в одной
  строке не сводятся к первой. Все примечания остаются в исходной ячейке.
  Для явного `28.09 перенос на 12.10` дополнительно выделяются `from_date`
  и `to_date` в `changes`; время и отмена основной пары не выводятся автоматически.
- У изменения без собственного места наследуется единственное место основной
  записи. `place_inherited=true` и `place_source` показывают происхождение,
  исходная ячейка не меняется. Если основных мест несколько, выбор не делается.

По согласованному правилу остальные полные адреса текущего листа сохраняются
как **дополнительные площадки / места партнёров** (`venue.kind=additional`,
`kind=additional_address`). Название организации и координаты могут оставаться
пустыми: категория не означает подтверждённую принадлежность партнёру.
Адрес и подпись помещения сохраняются буквально. У дополнительной площадки
в `resource_policy` заданы `reserve_room=false`, `allow_new_assignments=false`,
а `block_attendees`, `block_teacher` и `travel_time_required` остаются `true`.
Это готовое занятие ПД; генератор не получает разрешения ставить туда новые пары.
Классификация также сохраняется у датированных примечаний в `place_details`,
не превращая примечание без времени в дополнительное занятие.

Два адреса из текущего листа отдельно подтверждены как университетские:
Прянишникова, 2А и Автозаводская, 16с13 (гараж). Для них `venue.kind=university`,
сохранена ссылка на источник, а `reserve_room=null`: площадка установлена,
но помещение ещё не сопоставлено с БД. `allow_new_assignments=false` до такой
привязки. Совпадения только улицы недостаточно; например, Автозаводская 23А
не совпадает с подтверждённым университетским адресом. Это классификатор
текущей выборки, а не полный реестр всех зданий Политеха.

В `addresses.html`, `addresses.json` и `addresses.csv` перечислены
24 адресные подписи основных блоков и ещё три адреса из датированных примечаний:
всего 27 вариантов в 43 проектах, с привязкой к ячейкам и датам:
25 дополнительных вариантов адресов и два университетских.

Это правила и нормализованные данные прототипа. Проверенные интервалы ПД
подключаются к решателю через `manage.py import_pd_schedule` по явным ID
проектов, преподавателей и комнат; см. раздел «Фиксированное расписание ПД»
корневого README. Парсер сам импорт не запускает. Учитываются участники,
преподаватель, сопоставленная университетская комната и заданный запас на дорогу.
Маршруты и полноценное применение календарных отмен/переносов ещё не реализованы.

Порядковый номер в таблице не является внешним ID проекта. `project_id=null`:
сопоставление со справочником задаётся отдельно в файле импорта, а связи
«студент → проект» должны существовать в `ProjectEnrollment`.
Одноимённые проекты и варианты `[1]`/`[2]` не объединяются.
Списка студентов, полных границ семестра и правил повторения по неделям
в этих данных нет. Датированные изменения требуют проверки и последующего
календарного слоя. Готовые датированные интервалы сервис импорта сохраняет,
а недельный решатель использует консервативное объединение занятости в периоде.
Неразобранные календарные примечания останавливают импорт выбранного проекта.

## Физкультура

В предоставленном PDF пять страниц — пять интервалов времени. Каждая
страница содержит шесть дней; внутри дня есть название активности
и одна или несколько ячеек с местами проведения. Парсер восстанавливает
границы по линиям таблицы, а не по порядку текста всей страницы.

Текстовый слой читается без OCR. Профиль `mospolytech-pe-autumn-2026`
учитывает линии толщиной около 0.48 pt и исключает подчёркивания текста.
Для другого шаблона или скана потребуется отдельная проверка/профиль.
При отсутствии ожидаемых заголовков, текста или единственного интервала
страница вызывает явную ошибку. Адрес без связанной активности остаётся
в `orphan_place_cells`, не исчезает из результата.

Запись означает предложение занятия, а не назначение студенту. В ней:
день, буквальное время, активность, места, страница, координаты, фрагмент
источника и предупреждения. Несколько мест остаются списком с
`choice_mode=available_options_unspecified`: источник не объясняет порядок
выбора места. Названия «пауэрлифтинг, кроссфит» и «ОФП / футзал» сохраняются
целиком. По уточнению пользователя обе активности доступны, посетитель выбирает
на месте: `activity_choice_mode=on_arrival`, варианты — в `activity_labels`.
Предложение не дублируется в виде двух обязательных занятий.

СМГ помечается `health_group=special_medical_group`; такие предложения нельзя
считать доступными каждому студенту. Преподаватели, вместимость, допуск,
правило посещения дважды в неделю и точные даты периода из PDF не выводятся.

## Проверка

```sh
uv run --no-project --python 3.12 --with pdfplumber \
  python -m unittest discover -s prototypes/activity_parser -p 'test_*.py'

python -m prototypes.activity_parser.check_sample output/parser-prototype/activities
```

51 тест проверяет объединённые ячейки, координаты, несколько аудиторий,
переносы/даты, нестандартное время, СМГ и безопасный экспорт. Отдельная
контрольная выборка в `fixtures/verified_sample.json` проверяет реальные
выгрузки и хеши источников; парсеры её не читают.

Изначально предупреждения были у 96 проектов ПД. Исправлен разбор подписей,
аудиторий и ФИО в примечаниях, включая три случая ошибочной привязки помещения
НАМИ к университетской локации по умолчанию. Полные адресные подписи основных
блоков есть в 37 проектах, ещё у шести — в датированных примечаниях.
Принадлежность места нельзя определять только по форме записи адреса.

После предыдущих исправлений было 74 проекта ПД с предупреждениями.
После классификации дополнительных площадок осталось 43: календарные
исключения, привязка помещений пяти проектов на университетских площадках
и замены преподавателей. Снятое предупреждение о классификации адреса
не означает, что помещение, партнёр или маршрут независимо проверены.
У физкультуры осталось 37 предупреждений СМГ; 30 объединённых активностей
получили правило выбора на месте. Количество интервалов и предложений сохранено.

Первый документ: 323 проекта ПД, 669 явно записанных интервалов;
в PDF — 150 предложений занятий с 203 местами, без потерянных ячеек адресов.
Проверка выборки не означает ручную проверку всех значений. У всех записей
`review_required=true`, включая записи без предупреждений. Сохраняются
снимки HTML/PDF, SHA-256 и время разбора для воспроизводимости.

Следующий шаг для реальных данных: проверить выбранные записи, подготовить
сопоставление проектов/помещений и состав `ProjectEnrollment`, затем выполнить
импорт ПД. Проверку доступных вариантов физкультуры ещё предстоит подключить.
