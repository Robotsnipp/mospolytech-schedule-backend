# Прототип разбора сканированного учебного плана

Вопрос: можно ли получить проверяемые строки нагрузки из предоставленного
`09.03.01_D_WT_UP.pdf`? Прототип не пишет в БД и не готов для автоматического импорта.

## Запуск

Первичное распознавание требует macOS с Apple Vision, поддержкой `ru-RU`,
Swift/Xcode Command Line Tools и uv. Файл остаётся на компьютере, облачный OCR
не используется. Python-зависимости заданы в заголовке скрипта (PEP 723),
производственные зависимости Django не меняются.

Из корня репозитория:

```sh
uv run --no-project --python 3.12 prototypes/curriculum_parser/parse.py \
  /path/to/09.03.01_D_WT_UP.pdf \
  --output output/parser-prototype/09.03.01_D_WT_UP
```

Повторить преобразование без OCR: та же команда с `--reuse-ocr`.
Кэш проверяется по SHA-256 источника, версии схемы, ревизии алгоритма и профилю.
Для полного обновления распознавания запустить без этого флага.

## Результат

- `curriculum.json`: метаданные, дисциплины, суммарные часы по видам,
  аудиторные часы по семестрам, формы контроля, предупреждения и исходный текст ячеек.
- `curriculum.csv`: плоская таблица исходных значений OCR с предупреждениями,
  UTF-8 BOM для открытия в табличном редакторе.
- `review.html`: просмотр результата рядом с изображением каждой строки.
- `source.png`, `row-*.png`, `cell-*.png`, `ocr.json`: материал для сверки.
- `excluded_rows`: явный список исключённых заголовков/итогов с исходными значениями.

Каждая строка имеет `review_required=true`, включая строки без предупреждений.
При расхождении вариантов OCR спорное поле остаётся `null`; оба варианта
сохраняются в `ocr.json`. CSV содержит именно исходные значения с префиксом `raw_`.
Число `confidence` сообщает уверенность OCR, а не доказанную точность.
Пустые/нечитаемые числа остаются `null`; подозрительное `9` в семестре
не превращается автоматически в `6`. Нормализация похожих символов в кодах
дисциплин явно отмечается. Элективные строки помечены отдельно: они могут
быть альтернативами, а не обязательной нагрузкой каждого студента.

## Ограничения и результат прогона

Профиль `mospolytech-2025-full-time` привязан к расположению таблицы и
восьми семестрам конкретного одностраничного очного плана. Координаты и небольшой
перекос сетки заданы в профиле. Для другого шаблона, заочной формы и многостраничных
планов потребуется отдельная проверка/профиль. Общего распознавателя таблиц здесь нет.
Блоки практик, ГИА и факультативов пока не входят в область извлечения.

На предоставленном очном плане получены 68 кандидатов дисциплин и 9 исключённых
строк заголовков/итогов. В первом варианте OCR суммы видов занятий и семестров сходились, но визуальная
сверка выявила ошибку СРС 90 → 06. Поэтому добавлено второе распознавание с другой
предобработкой: расхождения оставляются неизвестными. На контрольном прогоне
расхождения обнаружены в 6 строках; автоматические сверки и предупреждения
сохранены в JSON. Выборочно сверены изображения строк;
полная ручная верификация всех ячеек не проводилась. Формы контроля и коды требуют
проверки, особенно одиночные цифры 6/9.

В исходнике часы лекций/семинаров/лабораторных даны суммарно по дисциплине,
а по семестрам указана только сумма аудиторных часов. Для многосеместрового
предмета прототип сохраняет эту неоднозначность: разбивка видов по семестрам
остаётся `null`. Для односеместрового предмета переносит доступные суммарные
значения. Самостоятельная работа не смешивается с аудиторной нагрузкой.
