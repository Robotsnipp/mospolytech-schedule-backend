# Условия и критерии генерации расписания

Единый перечень правил, по которым решатель CP-SAT строит недельный шаблон.
Если правило меняется, правят код и этот файл вместе. Числовые веса живут в
`schedule_generator/services/config.py`, дни недели — в `services/day_rules.py`.

Термины (пара, слот, локация, поток) определены в `CONTEXT.md`.

## Как читать

- **Жёсткое** правило нарушать нельзя: пара, которую иначе не поставить, остаётся
  неразмещённой (статус `PARTIAL`, запись в `GenerationIssue`).
- **Мягкое** правило штрафуется в целевой функции. Решатель нарушает его только
  ради размещения нагрузки: награда за пару (`REWARD_PLACED = 100`) больше
  любого одиночного штрафа.

## Жёсткие правила

| Правило | Где |
|---------|-----|
| Лекция потока идёт в один слот недели; все группы потока слушают её одновременно | `constraints.add_lecture_single_slot` |
| В аудитории в слоте не больше одного очного занятия | `constraints.add_room_exclusivity` |
| Группа или студент в слоте занят не более чем одним занятием | `constraints.add_attendee_exclusivity` |
| Преподаватель ведёт не более одного занятия в слоте | `constraints.add_teacher_exclusivity` |
| ПД только пн и ср; обычные пары вт, чт, пт, сб; внеучебка и ДПО в любой день | `day_rules.py`, `constraints.add_day_restrictions` |
| Вместимость аудитории не меньше числа слушателей; онлайн-занятие аудитории не занимает | `generator._build_variables`, `constraints.link_onsite_room_vars` |
| Участник не бывает на двух разных локациях в одном слоте | `constraints.add_location_consistency` |
| Участник не бывает на разных локациях в соседних слотах одного дня (дорога занимает час, перерыв короче) | `constraints.add_location_consistency`, `config.TRAVEL_BUFFER_SLOTS` |
| Отключённые аудитории (`is_active=False`) в генерации не участвуют | `generation.run_generation` |
| Физкультура не участвует в генерации | `enums.NON_GENERATED_LESSON_TYPES` |

Правило о соседних слотах отключается значением `TRAVEL_BUFFER_SLOTS = 0`.
Аудитории без корпуса в правилах о локациях не учитываются.

## Мягкие правила (штрафы)

| Критерий | Вес | Где |
|----------|-----|-----|
| Окно между занятыми слотами группы или студента | `PENALTY_WINDOW` | `objectives.collect_window_penalties` |
| Больше `max_pairs_per_day` пар у преподавателя в день | `PENALTY_TEACHER_OVERLOAD` | `objectives.collect_teacher_overload_penalties` |
| Усталость дня выше комфортного уровня | `PENALTY_FATIGUE_EXCESS` за единицу | `objectives.collect_fatigue_penalties` |
| Самый тяжёлый день среди всех групп | `PENALTY_FATIGUE_PEAK` за единицу | `objectives.collect_fatigue_penalties` |
| Пара не в «своё» время преподавателя (жаворонок или сова) | `PENALTY_CHRONOTYPE` за пару | `objectives.collect_chronotype_penalties` |
| Группа занята больше дней, чем позволяет режим подготовки к сессии | `PENALTY_FREE_DAY_VIOLATION` за день | `objectives.collect_free_day_penalties` |

### Индекс усталости

Усталость группы за день считается линейно по занятым слотам:

```
усталость = FATIGUE_PAIR_WEIGHT * (число пар)
          + FATIGUE_EARLY_WEIGHT * (есть пара в слоте <= EARLY_LESSON_NUMBER)
          + FATIGUE_LATE_WEIGHT  * (число пар в слотах >= LATE_LESSON_NUMBER)
```

Окна и переезды в индекс не входят, их считают отдельные метрики. Формула
реализована один раз в `services/wellbeing.py`, а ограничения решателя и отчёт
`GET /api/schedule/runs/<id>/wellbeing/` используют те же константы.

Решатель делает две вещи: штрафует превышение `FATIGUE_COMFORT_LEVEL` для каждой
группы и каждого дня и штрафует максимум по всем группам (минимакс). Поэтому
расписание, удобное «в среднем» с одним ужасным днём, проигрывает ровному.

### Хронотип преподавателя

`Teacher.chronotype`: `EARLY` (жаворонок) штрафуется за пары с номера
`CHRONOTYPE_EARLY_BAD_FROM`, `LATE` (сова) за пары до номера
`CHRONOTYPE_LATE_BAD_UNTIL`, `NEUTRAL` не штрафуется.

### Режим подготовки к сессии

Недельный шаблон не знает дат экзаменов, поэтому режим выражен числом свободных
дней: параметр `free_days_per_group` запуска генерации. Группа должна занимать не
больше `(доступные ей дни) - free_days_per_group` дней, остальные остаются на
подготовку. Нарушение мягкое: полнота размещения важнее.

## Перепланирование

`POST /api/schedule/replan/` строит новый запуск из существующего. Пары, которых
сбой не касается, закреплены бонусом `PIN_BONUS` за сохранение слота и аудитории,
поэтому решатель двигает только затронутое. Закрепление мягкое: если старый
запуск противоречит новым правилам, модель остаётся реализуемой.

## Что правила не гарантируют

- `SOLVED` означает, что вся нагрузка размещена, а не что мягкие правила
  выполнены. Качество оценивают метрики запуска.
- Недельный лимит преподавателя хранится, но не применяется.
- Известные проблемы генератора перечислены в `.agents/planning.md`.
